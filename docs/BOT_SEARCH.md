# Поиск квартир и лента Telegram

Пользователь создаёт именованные наборы поиска: название (до 40 символов), город,
комнатность и минимальный/максимальный бюджет USD.

«Критерии» показывает список наборов с городом, комнатностью и бюджетом каждого.
Здесь можно создать, отредактировать или удалить набор. Новый набор сохраняется
выключенным; настройка не снимает общую паузу и не включает поиск.

«Поиск» показывает общую активность поиска и позволяет включать/выключать
конкретные наборы, а также ставить весь поиск на паузу и возобновлять его.
Редактирования наборов здесь нет. Пустой список включённых наборов останавливает
подбор, сохраняя сами наборы и избранное. Длинные списки разбиты на страницы.

После включения бот автоматически отправляет **только новые объявления**.
У каждого набора отдельное начало наблюдения (`started_at`): включение и
редактирование начинают новый период только для этого набора.
Остальные наборы продолжают поиск без сброса общего курсора. После общей паузы
все наборы применяются только к объявлениям нового периода, без накопленного списка.

Каждое совпадение — отдельное сообщение с фото, ценой, адресом, характеристиками,
временем Kufar и кнопками «В избранное», «Открыть на Kufar».
В карточке написано **«Подходит наборам: Для себя, Родителям»** — перечисляются все
включённые наборы, которым подошла квартира. Одна квартира отправляется один раз,
даже если совпали несколько наборов. Если фото недоступно или подпись слишком
длинная, приходит текстовая карточка; названия наборов сохраняются полностью.

Ручной проверки актуальности и её кнопок нет. Старые кнопки проверки не запускают
обращений к Kufar. Свайпов и дайджестов со счётчиком в интерфейсе также нет.
Команды: `/start`, `/criteria`, `/favourites`, `/settings`, `/search`, `/help`.

## Что считается новым

Должны одновременно выполняться условия:

- ID впервые обнаружен после курсора пользователя;
- `list_time` не раньше начала наблюдения совпавшего включённого набора и не в недопустимом будущем;
- квартира активна, не скрыта администратором и соответствует хотя бы одному включённому набору.
- если у набора задано начало наблюдения, первое обнаружение ID также должно быть после этого момента.

В `listing_deliveries` уникальна пара `(telegram_id, ad_id)`. Сдвиг `list_time`,
повторный скрейп, очистка избранного и смена критериев не отправляют известный ID
повторно. Изменения цены и даты продолжают сохраняться в самом объявлении.
У объявления без корректного `list_time` нет автоматической отправки.
Поздно появившееся в поиске объявление с датой внутри периода наблюдения учитывается.

Скрейпер сохраняет данные по мере обхода страниц и после появления новых ID
сразу будит очередь доставки, не ожидая окончания обхода всего города; резервный проход
выполняется раз в 10 секунд (`NOTIFICATION_SCAN_INTERVAL`). Интервал и число страниц быстрого обхода Kufar
задаются в админке Tasks; полный рефреш имеет отдельный интервал в минутах. Это задержка от нашего обнаружения: API источника,
продолжительность обхода и ограничения Telegram могут добавлять время.
Интервалы настраиваются операционно; пользовательских дайджест-интервалов нет.

В outbox сохраняется снимок совпавших наборов (`matched_profiles`: ID и название).
Переименование или удаление набора не меняет подписи уже отправленных карточек;
этот же снимок отображается при открытии из избранного.
Также фиксируются pending/processing/delivered/cancelled, lease, число попыток,
время повтора и ID сообщения Telegram. Ошибки повторяются с backoff; rate limit
откладывает и следующие карточки этого пользователя. Каждая успешная карточка
подтверждается отдельно. Незавершённые lease восстанавливаются. Курсор поиска
и повторная доставка независимы: одна неотправленная карточка не блокирует
обнаружение следующих совпадений. Перед отправкой заново проверяются критерии,
пауза и видимость объявления. Перед отправкой список совпавших наборов вычисляется
заново: выключенные, удалённые и переставшие подходить наборы убираются. Если остаётся
хотя бы один — карточка отправляется с актуальными названиями; если нет — отменяется.
Общая пауза отменяет ожидающие карточки. Изменение одного набора не отменяет
совпадений по другим наборам.

Доставка at-least-once: авария после принятия сообщения Telegram, но до commit
может дать повтор. Уникальность ID предотвращает повторную постановку обычным
обходом, но не устраняет это окно внешней доставки.

## Избранное и архив

«Актуальные» — сохранённые объявления, активные и видимые в каталоге.
«Архив» — сохранённые объявления, снятые источником или скрытые администратором.
Статус определяется по текущему состоянию объявления, поэтому перенос происходит
автоматически. Если тот же ID снова активен, он возвращается в актуальное избранное
без повторной отправки в ленту. Само сохранение, время сохранения и ID остаются.

В обоих разделах есть страницы по 10 квартир. Можно открыть карточку или удалить одну квартиру. «Очистить избранное» удаляет актуальные
сохранения пользователя, «Очистить архив» — архивные. Для массовой очистки есть
подтверждение; при подтверждении статус проверяется заново. Очистка не удаляет
объявления из общего каталога и не затрагивает других пользователей.

## Проверка актуальности

Раз в 5 минут (`AVAILABILITY_CHECK_INTERVAL_SECONDS`) проверяются города,
в которых есть сохранённые квартиры. Проверка проходит **все страницы поиска**,
без повторной загрузки сотен детальных карточек. Полная ежедневная сверка
с деталями сохраняется отдельно. Это фоновое обслуживание каталога для автоматического
архива; пользовательского запуска проверки нет.

Только завершённый обход позволяет снять отсутствующий ID. Ошибка сети,
некорректная пагинация или ошибка сохранения оставляют прежние статусы.
Ответ детальной карточки 200 сам по себе не доказывает наличие в текущей выдаче.
Проверка означает присутствие в Kufar: фактическую доступность квартиры у владельца
бот подтвердить не может.

## Обновление

Миграция `20261015_0006` создаёт индивидуальный outbox, сохраняет пользователей,
критерии, избранное и историю старых дайджестов. Ожидающие старые дайджесты отменяются,
курсор ставится на момент обновления, чтобы каталог не превратился в массовую
рассылку. Существующая пауза сохраняется. Legacy-таблицы просмотренности и интервалов
остаются совместимыми с историческими данными, но новый интерфейс их не использует.
Перед миграцией сделать backup и остановить старые процессы записи.

Миграция `20261015_0007` превращает прежние критерии в включённый набор «Основной»,
сохраняет его поля, начало наблюдения, пользовательскую паузу, избранное и курсор.
Добавляется снимок совпадений в доставках. Старые доставленные карточки без снимка
не получают вымышленных подписей. Новые наборы не вызывают повторную отправку ID,
которые уже есть в outbox. Откат с несколькими наборами требует backup: миграция
не удаляет дополнительные наборы ради возврата к старой схеме.
